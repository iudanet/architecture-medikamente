# Задание 3. Data Encryption at Rest and In Transit

## 1. Классификация данных

Уровни чувствительности:
- **С3** — строго конфиденциально: врачебная тайна и специальные категории ПДн;
- **С2** — конфиденциально: ПДн и коммерческая тайна;
- **С1** — для внутреннего использования;
- **С0** — публичные данные.

Состояния данных: хранение, передача, использование.

| Данные | Тег | Чувствительность | Состояние / где | Профиль риска | В чём необходимость защиты | Инструменты защиты |
|---|---|---|---|---|---|---|
| Медкарта: диагнозы, анамнез, заключения | `PHI` | С3 | Хранение: БД ЭМК, файлы. Использование: МИС | Утечка, НСД сотрудниками | Врачебная тайна (323-ФЗ ст. 13), спецкатегория ПДн (152-ФЗ ст. 10), УЗ-2/3 по ПП № 1119 (уровень зависит от типа актуальных угроз) | Полевое шифрование AES-256, ключи в Vault + HSM, ABAC, аудит чтения, SIEM/UEBA |
| Результаты анализов | `PHI` | С3 | Передача: лаборатория ↔ МИС. Хранение: ЭМК | Перехват, отправка не тому пациенту | Врачебная тайна; передача третьему лицу только по поручению | mTLS, подпись webhook, `sample_id` вместо ФИО, проверка владельца на API Gateway |
| Идентификационные данные: ФИО, ДР, паспорт, СНИЛС, полис | `PII.Identity` | С2 | Хранение: CRM. Передача: порталы | Кража базы, использование для мошенничества | 152-ФЗ ст. 19, штрафы КоАП 13.11 | Шифрование БД (AES-256), полевое для документов, маскирование в UI, TLS 1.3 |
| Контакты: телефон, email | `PII.Contact` | С2 | Хранение: CRM. Передача: уведомления | Спам, фишинг от имени клиники | 152-ФЗ | Полевое шифрование, динамическое маскирование, токен в сервисе уведомлений |
| Согласия и запросы субъектов | `PII.Identity` | С2 | Хранение: сервис согласий | Подмена, потеря доказательной базы | 152-ФЗ ст. 9, 21: доказательство согласия и его отзыва | Неизменяемый журнал (append-only), подпись записи, бэкап |
| Договоры, платежи | `Financial` | С2 | Хранение: CRM, 1С. Передача: платёжный шлюз | Искажение, раскрытие услуги | 152-ФЗ; бухгалтерский учёт; услуга раскрывает медсведения | Шифрование БД, TLS, обобщённое наименование услуги, контроль целостности |
| Данные карт | `Financial` | С3 | Передача: эквайер | Компрометация карт | PCI DSS (у эквайера) | Токенизация у эквайера, хранение в системе запрещено |
| Кадровые данные сотрудников | `PII.Employee` | С2 | Хранение: 1С. Передача: банк, ФНС, СФР | Утечка ПДн сотрудников | 152-ФЗ, ТК РФ гл. 14 | Шифрование БД и бэкапов, доступ по группе AD; банк — ДБО с ЭП, ФНС и СФР — ЭДО с ГОСТ-шифрованием |
| Учётные данные, ключи, сертификаты | `Secret` | С3 | Хранение: Vault. Использование: сервисы | Компрометация всей системы | Защита всех остальных классов | Vault, HSM, ротация, короткоживущие токены, MFA |
| Журналы аудита | `Internal` | С2 | Хранение: Elastic, SIEM | Удаление следов нарушителем | Приказ ФСТЭК № 21 (РСБ), расследование инцидентов | Append-only, отдельный контур, доступ только ИБ, срок хранения |
| Псевдонимизированные и агрегированные данные | `Internal` | С1 | Озеро данных `verified`/`golden`, BI | Повторная идентификация | Data Minimization; псевдонимизированные данные остаются ПДн, обезличенные витрины (k-анонимность) — нет | Детерминированная псевдонимизация, k-анонимность витрин, доступ по Ranger |
| ТМЦ, закупки | `Internal` | С1 | Хранение: 1С | Искажение учёта | Коммерческая тайна | RBAC, шифрование бэкапов |
| Прайс, расписание, ФИО врачей | `Public` | С0 | Портал | Подмена | Целостность | TLS, контроль изменений |

## 2. Базовые инструменты защиты

| Состояние | Инструменты |
|---|---|
| Хранение (at rest) | Шифрование дисков серверов (LUKS / BitLocker); шифрование БД PostgreSQL на уровне томов + полевое шифрование `PHI`/`PII` в приложении (AES-256-GCM, envelope encryption); шифрованное объектное хранилище (MinIO SSE-KMS); шифрование бэкапов; ключи отдельно от данных — Vault + HSM |
| Передача (in transit) | TLS 1.3 на всех внешних и внутренних HTTP; mTLS между сервисами и с лабораторией; ГОСТ TLS (КриптоПро) для ЭДО и госсистем; VPN между филиалами; запрет SMB1 и шифрование SMB3 на оставшихся файловых ресурсах |
| Использование (in use) | RBAC/ABAC (Keycloak; Ranger — в озере данных, нативные роли и row-level политики — в PostgreSQL и ClickHouse), динамическое маскирование, MFA, Zero Trust (проверка каждого запроса на API Gateway), минимум данных в ответах API |

## 3. Автоматизированный контроль

| Что контролируется | Средство |
|---|---|
| Появление неразмеченных ПДн в БД, хранилищах, почте | DLP + сканер каталога (Apache Atlas), алерт |
| Релиз с полями `PHI`/`PII` без тега или правила защиты | Проверка в CI по каталогу, блокировка релиза, метрика → VictoriaMetrics/Grafana |
| Нетипичный доступ: массовое чтение медкарт, доступ ночью, доступ не к своим пациентам | SIEM/UEBA по журналу аудита (Elastic) |
| Срок хранения и запросы субъектов | Задачи удаления по тегу `Retention`, контроль SLA запросов в сервисе согласий |
| Состояние шифрования и ключей | Мониторинг сертификатов (срок), ротация ключей Vault, алерт на нешифрованные тома и бакеты |

## 4. Реестр программных и аппаратных средств защиты

| Средство | Класс | Назначение | Где применяется |
|---|---|---|---|
| Keycloak (федерация с AD) | IAM | SSO, MFA, OIDC, роли и атрибуты | Порталы, приложение, МИС, CRM |
| API Gateway + проверка владельца | Контроль доступа | Единая точка входа, фильтрация полей контракта | Все внешние и партнёрские API |
| Apache Atlas | Каталог данных | Теги, классификация, lineage | Все хранилища и потоки |
| Apache Ranger | Политики доступа | Доступ и маскирование по тегам | Озеро данных (MinIO, Trino) |
| Apache NiFi | Управление потоками | Загрузка с шифрованием и псевдонимизацией полей | Аналитический слой |
| HashiCorp Vault | Управление ключами и секретами | Ключи шифрования, секреты, ротация | Все сервисы |
| HSM (сертифицированный ФСБ) | Аппаратное | Хранение мастер-ключей | Контур Vault |
| КриптоПро CSP | СКЗИ | ГОСТ-шифрование, электронная подпись | ЭДО, обмен с госсистемами |
| VPN-шлюзы (ГОСТ, например ViPNet) | СКЗИ | Каналы между офисом, филиалами и ЦОД | Сеть |
| DLP (InfoWatch Traffic Monitor / Solar Dozor) | Предотвращение утечек | Контроль почты, веба, носителей | Рабочие станции, почта |
| Средство защиты от НСД (Secret Net Studio) | СЗИ от НСД | Контроль устройств и носителей, замкнутая среда | Рабочие станции и серверы |
| Elastic (журнал аудита) + SIEM (MaxPatrol SIEM / KUMA) | Аудит, корреляция | Журнал доступа, UEBA, инциденты | Все системы |
| VictoriaMetrics + Grafana | Мониторинг и алертинг | Метрики проверок релиза, алерты ИБ | Платформа |
| Резервное копирование с шифрованием | Доступность | Бэкапы БД, хранилищ и 1С вне офиса | Все хранилища |

Для нейтрализации актуальных угроз применяются СЗИ и СКЗИ, сертифицированные ФСТЭК и ФСБ (приказ ФСТЭК № 21, п. 4).
